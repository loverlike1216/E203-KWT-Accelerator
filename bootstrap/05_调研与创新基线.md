# 技术事实、最新研究与创新边界（2026-10-17）

## I. 已知官方事实（源自赛题指南）

- KWT-1 官方模型，固定 ARM commit `237e4097`，12 层、64 维、1 头、前馈 64→256→64、PostNorm；本科必做**第一线性层**，即 99×64 @ 64×256 + 256 bias。
- E203 RISC-V CPU；System Bus 或 NICE 接入；系统共享 512 KB；加速器内部使用规定 16 位 SRAM 宏；150 MHz 时钟；ASIC 新增面积 2.25 mm² 上限。
- 最高本科归一化 RMSE 3%，RTL/software bit-exact；初赛本科提交 1–3 项；决赛提交自主创新和正式 PPA 报告。
- 不允许微调、蒸馏、训练、不允许 CPU 代算，不能增设外部存储。
- 面积/时序/功耗必须以官方统一配置核对。

## II. 参考仓库与需验证的歧义

1. `https://github.com/riscv-mcu/e203_hbirdv2` 是开源参考。其 README 明确存在 NICE 支持，SDK 为 `https://github.com/riscv-mcu/hbird-sdk`。正式比赛平台才是接口/存储/测试的事实源。
2. `https://github.com/ARM-software/keyword-transformer` 的公开 README 表格把 KWT-1 `mlp-dim` 写为 `128`，但题目要求 `256`；指定 `kwt1/flags.json` 则显示 `mlp_dim:256`。必须实际加载 `best_weights` 列出第一线性层 12 组 tensor shapes，解释或升级争议，禁止直接依任一描述想当然修改模型。
3. 官方真实 512 KB SRAM 分配、bus 带宽/等待、已实现接口均需要代码和脚本审计；不能从公开 README 推断比赛工程实现一致。

## IV. 建议架构/研究假设

- **最优先可落地**：低并行 output-stationary GEMM，优先保证数值、官方 SRAM、E203 真实闭环，保底 1/4/8 MAC 可配置；达到面积/时序后再对比 16 MAC。
- **主创新假设**：在官方“每任务冷启动、加载和总线等待计时”规则下，采用面向固定 99×64×256 的 SRAM bank-aware tiling、输出驻留和预取调度，降低总 SRAM 流量/CPU 等待/任务周期/能耗。
- **可选方向**：分层量化精度参数（十二层相同几何形状，不能声称“动态形状 tile”必有收益）；任务内双缓冲合法重叠。
- **风险**：访存瓶颈、宏数量导致面积超限、复杂精度对 bit-exact 要求、E203 总线受限、旧版 TF 环境不兼容。
- **反证要求**：优化后同条件任务耗时/能耗若未改进，不得仍称“有效创新”。若新的数值格式改善效率但破坏 3% 门槛，一票否决。

## V. 推荐比较与实验

Baseline：最低可用 P 的同数值规格输出驻留计算。

A：同 P 下改变 tile/blocking 和 SRAM staging；衡量 task cycles、SRAM reads/writes、buffer 资源、J/task。

B：可选内部 double buffer；衡量 E203/bus 等待与整体能耗。

C：可选数值配置；必须额外证明位精确、NRMSE、宏与 cell 面积收益。

A/B/C 均相同输入和参数加载规则、工艺角、时钟目标、netlist/PPA 口径。求出真实 Pareto points，不宣称算法首创。状态 `NOVELTY_NOT_CONFIRMED` 直到完成最近邻技术与自有机制的独立证据核查。

## VI. “7 天一次运行”取舍

先 `功能正确 + SoC 集成 + 正式综合`，再做可量化创新。对于本科比赛，可靠并完整的真实工程比无法运行的论文级宏大架构更有价值。
