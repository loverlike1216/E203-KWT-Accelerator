## 数值验收精确定义

针对层 L=1..12，样本集的所有输出元素：

`NRMSE[L] = sqrt(mean((decoded_Y[L]-float_ref_Y[L])**2)) / max(sqrt(mean(float_ref_Y[L]**2)), 1e-8)`。

`MAX_L NRMSE[L] <= 0.03`。注意“每层汇总样本再求 RMSE”，而不是“取每个样本的 NRMSE 最高值”。正式组委会选取 600 条样本，如清单尚未发布，不得声称已经完成该集合的最终评测。仿真另外验证 `RTL_raw_output == bit_exact_model_raw_output`（无误差容忍）。

## PPA 公平性

- 全部效率指标必须同一 `rtl/netlist/config/tool/corner/clock/workload`。
- task start：从输入**及参数**装载开始；end：所有输出写回结束。每任务起始清空相应参数/任务数据缓存。
- 平均功耗含全部规定对象；公式 `J/task = P_avg*sum(duration_i)/number_of_tasks`。
- 确认是否存在无限期 fallback：只要正式工艺/官方工具缺失，正式 PPA 无法 PASS。
- 150MHz 目标周期约 6.667 ns；要有正裕量，不能仅“仿真 150MHz 时钟”便当作 STA pass。

## 报告格式

每条结果：`ID | Status PASS/FAIL/UNVERIFIED/BLOCKED | Test command | tool version | input hash | output/report path | actual value | limits | notes`。

最终验收只用：
- `ACCEPT`：本科硬性任务和主要正式验证**全部通过**，阻塞 0、Critical bug 0，证据齐全。
- `ACCEPT WITH LIMITATIONS`：有明确非阻塞缺陷或可接受的非必做创新不足，但不能含未通过的必做核心门槛并仍称达标。
- `REVISE`：必做门槛失败，或缺失正式验证关键证据，不可宣称完整竞赛成果。

任何失败后不得修改官方验收条件来降低难度。工程报告可注明 `ALTERNATIVE_VALIDATION` 但不得等同正式验收。
