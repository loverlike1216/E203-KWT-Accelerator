# E203-KWT-1 芯片设计赛道 | Codex 一次性开发包

编制日期：2026-10-17。适用：本科生组；候选项目 v1；用户拟使用 Codex 6.1 Sol / XHigh。

## 交付文件

1. `01_CODEX_启动词.md`：首次在新工作区下发的启动词。
2. `02_CODEX_总指令.md`：正式工程开发、验证、优化、交付主指令。
3. `03_附件与资源清单.md`：必须本地提供的竞赛文件、可自动下载的开源资源与许可隔离规则。
4. `04_验收与质量门禁.md`：按官方赛题核验的验收矩阵，禁止“仿真演示冒充达标”。
5. `05_调研与创新基线.md`：相关技术研究、设计选择依据与创新约束。
6. `06_CODEX_续跑词.md`：同一 v1 中断后恢复，不把续跑误判为升级版本。
7. `PROJECT_INPUTS.template.yaml`：首次启动必须填写的工作区/正式仓库/平台路径等配置模板。
8. `OFFICIAL_RULES_用户提供.pdf`：原始上传的正式赛题指南副本。

## 使用顺序

1. 用户自己创建正式 GitHub Repository 和新的本地工作区。
2. 将本压缩包解压在新工作区的 `bootstrap/`（或你指定的准备区），保留原始赛题 PDF。
3. 把组委会正式 E203 平台、SRAM/标准单元库、脚本、许可相关资料置于 `inputs/official/` 或填写可访问的本地路径（不要上传到公开 GitHub）。
4. 填写 `PROJECT_INPUTS.template.yaml`，另存为 `PROJECT_INPUTS.yaml`；最重要的是 `project_id`、`repository_url`、`workspace_path` 必须是用户本人明确指定的真实值。
5. 在 Codex 中配置可执行的工作区和授权，模型如可选则选 6.1 Sol / XHigh；把 `01_CODEX_启动词.md` 文本发给 Codex，并提供全部本包文件。
6. Codex 一次接收完整目标后连续执行 Stage 0 → Stage 6；一般实现问题自主迭代，重大不可逆操作、升级版本、费用等保持人工门禁。
7. Codex 无法持续到完成时，使用 `06_CODEX_续跑词.md` 从仓库检查点恢复。

## 边界与承诺

- 这是**可执行的工程指令与约束包**，不是已完成的 RTL/SoC/ASIC 验证工程。
- 用户现有 ChatGPT 聊天的沙盒不是用户 PC 的 E: 盘；必须由 Codex 在用户新工作区真实执行安装/下载/编译/仿真/综合。
- 7 天是高强度冲刺时间预算，不是保证通过所有评测的承诺。
- `riscv-mcu/e203_hbirdv2` 是开源参考仓库，不得默认视为组委会正式定制平台，也不是用户自己的正式 GitHub 仓库。
- 赛题原 PDF、用户批准的决策、真实代码/工具证据优先于本说明；若发生冲突应标记并升级审查。
